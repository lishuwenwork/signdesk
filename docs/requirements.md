# SignDesk 需求文档

> 状态：**实现已集成；后端与发布验证通过，浏览器 E2E 待完成**。日期：2026-10-09。
> 代码集成于 `refactor/backend-ruoyi-style` 主工作区；`475c46a` 是实现前基线，当前实现尚未提交/推送。P1～P5 已完成；P6 浏览器验收被实际 E2E 未运行阻塞；P7 文档收尾见 [重构计划](refactoring-plan.md)。
> 本文描述当前实现及验收要求，不是尚待开发的目标草案。实际命令、110 项后端与 8 项前端验证、未验证范围见 [验证记录](validation.md)。技术实现见 [架构文档](architecture.md)。

## 1. 产品目标与边界

SignDesk 是个人使用、单实例运行的 cURL 请求与签到管理 Web 工具。用户在浏览器中管理平台、账号、完整请求及结果规则；服务器负责保存、定时、执行、记录与响应查看，关闭浏览器不影响后台任务。

本次重构解决两个问题：

1. 后端组织难以阅读：改为类似 RuoYi-Vue-Plus 的清晰分层，普通 CRUD 使用 MyBatis-Plus，避免 SQL 和弱类型 Map 混在业务代码里。
2. 未上线项目不需要历史负担：全部取消应用数据／备份加密，数据库建立新的单一 V1 基线，不实现旧库、旧加密备份的迁移或兼容。

### 1.1 已确认决定

| 项目 | 目标 |
|---|---|
| 技术栈 | Java 21、Spring Boot 4 / Spring MVC、SQLite、MyBatis-Plus、Hutool HTTP、Vue3 / JavaScript |
| 工程 | 同仓库 frontend / backend；生产发布一个包含前端的 JAR |
| 部署 | 单实例，SQLite 位于 JAR 外的本地数据目录；默认仅监听本机 |
| 代码风格 | controller、domain、domain.bo、domain.vo、mapper、service、service.impl；保持小型单体 |
| ID | 新业务主键使用 MyBatis-Plus 雪花 ID，Java、SQLite 和 API 保持字符串表达 |
| 数据保护 | 请求、响应、导出文件均不加密；不再需要主密钥或备份密码 |
| 新项目基线 | 只初始化新 V1；不升级旧库、不导入旧备份，不自动清空已存在的文件 |
| 重构原则 | 保留已有业务和执行安全语义，不借重构新增平台能力或重做前端设计 |

取消加密不等于取消 HTTPS/TLS，也不等于允许日志记录凭证。数据库和含完整请求的导出文件可能包含 Cookie、Token、签名和响应中的个人信息，用户应通过操作系统权限、磁盘与备份管理、私有网络控制访问。

### 1.2 不在本次范围

- 应用登录、用户／角色权限、Spring Security、JWT、Redis、多租户、多节点调度。
- 桌面运行时、独立生产前端服务器、微服务和若依公共模块整体迁入。
- 自动登录、Token 刷新、动态签名、验证码处理、多步变量传递。
- cURL 请求占位符／账号变量模板、任意 JavaScript 规则、自定义 Cron。
- 旧 UUID 数据转换、旧数据库迁移、旧加密备份解密或兼容。
- 宣称 Hutool 能完全复现浏览器指纹或全部 cURL 选项。

## 2. 功能需求

### FR-01 平台、账号与请求

- 平台支持新增、编辑、启停、删除；名称非空且最多 40 字符，备注最多 500 字符。
- 平台下有多个账号；账号别名非空且最多 40 字符，支持独立启停与删除。
- 账号下有多个请求；请求名称非空且最多 60 字符，支持新增、编辑名称／规则、启停、查看完整请求、更新 cURL、删除。
- 平台、账号和请求均启用，且请求未因凭证过期暂停，才允许发送。
- 删除平台级联清理账号、请求、模板、计划和相关记录；删除账号／请求清理各自关联数据。存在排队或运行中的关联任务时先拒绝删除，提示取消并等待结束。
- 配置编辑采用版本控制，陈旧提交返回冲突，不能静默覆盖其他页面的修改。

### FR-02 完整 cURL 与不可变修订

- 每个账号粘贴自己的完整 cURL，不自动共用或替换其他账号的凭证。
- 新增流程为“填写名称／可选模板、粘贴 cURL → 解析预览 → 检查结果规则 → 保存”。预览不会发送请求。
- 保存原始 cURL 和结构化请求快照；更新 cURL 新建修订并解除该请求的凭证暂停，不改写历史修订。
- 请求 ID、规则、计划和已有记录保留；更新凭证不会清除当日完成／待确认标记。
- 明文持久化不改变原始 URL、重复 Query、重复 Header、Body 字节和编码的保留要求。
- 完整请求只在明确打开详情时返回，不放入列表或浏览器持久存储。

### FR-03 同平台接口规则模板

- 一个平台可以保存多份“名称＋结果规则”模板，如签到、领取奖励、查询积分。
- 支持新增、编辑、删除，以及从已有请求保存为模板；模板不得存放 cURL、URL、Headers、Body 或账号凭证。
- 新增请求时仅可选择所属平台的模板；自动填写名称与规则，不修改已粘贴的 cURL、账号或启停状态。
- 套用后可手工编辑；覆盖已有手工改动前确认。关闭重开与切换平台时，不残留旧选择或迟到响应。
- 请求保存自己的规则副本，不动态继承模板；修改／删除模板不改变已有请求或队列快照。
- 不选模板或模板加载失败时，仍允许手工新增请求。

### FR-04 结果判断

规则支持 JSON 字段路径、严格类型的等于值、文本包含，以及基于用户输入响应的规则试算。数字 `0`、字符串 `"0"`、布尔和 null 必须区分；明确置空的分类保持禁用。不执行用户脚本。

| 执行状态 | 含义及处理 |
|---|---|
| queued / running | 已持久化排队／准备发送，不能靠页面内存代替 |
| success | 命中成功规则，记录当天完成 |
| already_done | 命中已完成规则，同样记录当天完成 |
| expired | HTTP 401 或命中过期规则，暂停该请求，等待更新 cURL |
| failed | HTTP／业务规则给出明确失败或发送前校验失败 |
| unknown | 超时、中断、无法判断、响应超限等，可能已完成，禁止自动重试 |
| skipped | 未发送：已完成、待确认、停用、补执行窗口过期等 |
| cancelled | 未发送的队列项被取消 |

保持当前分类顺序：HTTP 401 优先为 expired；其他非 2xx 先检查过期规则，4xx 为 failed，其余为 unknown；2xx 按 expired → failed → already_done → success 匹配，均未匹配为 unknown。响应超限或读取未完成不得当作完整响应命中成功。

旧修订返回凭证过期时，不得暂停已经更新为新修订的凭证。

### FR-05 手动执行、队列与取消

- 支持单请求、整个平台、全部已启用平台的手动执行。
- 手动入口先落库批次和队列项，再返回 202 和批次 ID；同一幂等键与平台组合只创建一次。
- 创建批次时冻结请求修订号、结果规则和必要计划参数，之后编辑配置不改动已排队快照。
- 同平台串行；跨平台限制并发，默认 2，范围 1～8；请求间隔按平台计划执行，默认 2 秒。
- 同一请求已有 queued/running 项时不重复入队；保留现有队列总量保护。
- 取消只处理尚未发送的任务；已发送请求按真实返回或不确定状态收尾，不把取消包装成安全重试。
- 发送前重新检查启停、取消、凭证暂停、业务日期和日标记。主动“重新执行”可忽略完成／待确认标记，但不绕过停用、凭证暂停等条件。

### FR-06 定时、补执行与恢复

- 每个平台独立设置每日／指定星期、多个时刻、Asia/Shanghai 或 UTC、请求间隔和补执行窗口。
- 默认每日成功后跳过；关闭后允许不同计划时刻重复执行，但未知结果仍阻止自动重发。
- 自动发生键为“平台 ID＋UTC 计划时刻”，不包含计划版本；编辑计划不能重放同一发生点。
- 生效时间限制新计划，已有批次保持自己的快照；错过时刻只考虑当前业务日期与允许窗口。
- 默认约每 5 秒扫描计划、每 500ms 调度队列；这是后台调度，不承诺精确到毫秒。
- 关闭页面不影响服务器；全局暂停只阻止新自动触发，不中断已有任务，手动入口仍可用。
- 重启时将上次 running 请求标记 unknown，并留下当日待确认标记；不能直接重放。queued 项重新检查发送条件后才继续。
- 完成日标记、待确认日标记、自动发生去重记录与执行日志保留周期互相独立，删除日志不得让当天任务重新发送。

### FR-07 执行记录与响应体

- 列表支持平台、结果、来源筛选及分页；默认每页 20，最大 100。
- 展示平台／账号／请求、实际请求修订、触发来源、业务日期、起止时间、HTTP 状态、耗时和固定安全摘要。
- 每次发送独立记录实际收到的最终响应体；成功、业务错误和 HTTP 错误都保留已收到的内容。受控重定向只保存最终或策略停止时的响应，不增加每跳历史。
- 响应体明文保存，详情按需读取，列表与批次摘要不附带正文。
- 保持 1 MiB 读取上限：超限保存前缀并标记截断；读取中断保留已收到部分并标记不完整；这些状态仍为 unknown。
- 明确区分空响应、未获取、未发送、未保存、部分和截断。不把客户端合成的错误文字当成服务端正文。
- 按字符集显示文本；二进制或无法解码的数据用 Base64 表示。HTML 只作为文本，不执行脚本；Base64 是编码，不是加密。
- 详情禁止缓存；关闭／卸载清除页面内容，迟到请求不得重填或覆盖另一个详情；完成后不轮询重复下载大正文。
- 默认保留 30 天，范围 1～365 天；响应随执行项删除，日标记不随之删除。进程中断来不及保存的响应不能补回，也不能为补录而重发。

### FR-08 全局设置与代理

- 保留暂停定时、并发、请求超时、记录保留天数及版本控制。超时默认 20 秒，范围 1～120 秒。
- 支持跟随 Java 启动代理、直连、无需认证的 HTTP 代理、SOCKS5 代理。
- 代理持久保存，影响新开始发送的请求，正在发送的请求继续原配置；不可用时不回退直连。
- 代理保存前校验模式、主机、端口，校验失败或版本冲突不部分写入。
- 不增加代理账号密码、不从 cURL 接受代理指令；继续校验 HTTPS 证书与主机名。

### FR-09 无加密导入导出

保留两个导出选项，但两者都是普通 JSON，不再输入密码：

| 内容 | 不含请求内容的配置 | 含完整请求的配置 |
|---|---|---|
| 平台、账号、请求名称和规则、模板、计划、执行及代理设置 | 包含 | 包含 |
| 完整原始 cURL | 不包含 | 包含明文 |
| 当日完成／待确认标记 | 不包含 | 包含 |
| 旧请求修订、执行历史、响应体、活动队列 | 不包含 | 不包含 |

- 默认不含请求内容；选择完整导出时明确提示文件含敏感信息，仍由用户主动点击下载，不上传外部服务。
- 使用新的明文格式标识；不识别旧密码加密文件，也不自动转换旧导出格式。
- 在一致的短事务中获取配置快照；配置内容上限 8 MiB（8,388,608 字节），导入文件上限 12 MiB（12,582,912 字节），统一按 UTF-8 字节计算，不能用 Java 字符数代替。
- 不含请求内容的模式只排除系统保存的请求快照，不能保证用户手工填入名称、备注、规则值的内容没有敏感信息；导出前仍需自行检查。
- 导入必须先预览结构和数量，再明确确认“替换全部配置”；不是合并导入。
- 结构、名称、ID、规则、父子关系、计划和大小全部校验通过，且队列空闲后，才能进入替换事务；任一步失败全部回滚。
- 导入保留配置中的 ID。当前请求修订重建为 1，不恢复历史；完整导入恢复当前 cURL 和日标记，不含内容的请求保持停用，更新 cURL 后才能启用。
- 导入后全局定时保持暂停，计划从导入时重新生效，不立刻补跑导入前的历史时刻。
- 无主密钥、密码、盐、nonce、PBKDF2、AES-GCM 或密钥迁移。普通文件校验不应被误称为身份验证或加密。

### FR-10 概览与部署

- 保留今日概览、下一次执行、近期记录、需处理任务和系统运行状态。
- 开发环境由 Vite 代理 `/api`，生产由 Spring Boot 同源提供前端和 API；服务器运行只要求 Java 21 和可写数据目录。
- 一份数据目录只有一个进程，SQLite 使用本地磁盘、WAL、外键与忙等待配置。
- 新版采用新 V1。遇到不符合新结构的数据库明确拒绝启动，不升级、不删除、不覆盖；开发者自行选择新的数据目录。

## 3. cURL 支持边界

本轮不扩大传输能力，保留解析器和执行器现有行为：

| 项目 | 支持／限制 |
|---|---|
| 格式 | 常见 Bash、Windows CMD；不执行变量、命令、外部文件 |
| 协议与 URL | ASCII HTTP/S URL，保留原始编码、重复参数；目标网络策略仍生效 |
| 方法 | GET、POST、PUT、DELETE、HEAD、OPTIONS；不支持 PATCH、GET Body、HEAD Body |
| Headers / Cookie | 有序、重复头及内联 Cookie；每次独立 HTTP 对象与 Cookie，不共享全局会话 |
| Body | UTF-8 内联 `-d`、`--data-raw`、`--data-binary`、`--data-urlencode`；按已声明语义生成并冻结字节 |
| 压缩 | gzip / deflate / identity；不承诺 br / zstd |
| 重定向 | 显式 `-L`，同来源最多 5 跳；保留 301/302/303/307/308 的现有方法转换和凭证边界 |
| 超时 | cURL 超时与全局上限取严格值，包含执行总期限 |
| 拒绝 | `@文件`、上传、命令管道、外部配置、代理选项、客户端证书、关闭 TLS 验证、强制 HTTP/2 及无法等价支持的语义 |

不偷偷规范化签名 URL、不默默丢弃选项，不读取 cURL 引用文件。预览中的完整内容不能被记录到日志。时间戳、一次性签名、IP 绑定和验证码仍可能使重放失效。

## 4. 非功能与代码质量要求

- **可读性**：按业务拆分 Controller、Service 接口／实现和 Mapper；实体、BO、VO 责任明确，不再用巨型 API 类、公开字段或大量 Map 承载业务模型。
- **简洁性**：普通 CRUD 用 MP；复杂 SQL 进入 XML。删除无调用代码、重复封装、旧兼容和加密实现，但不删除有效业务校验、事务与安全边界。
- **依赖控制**：保留现有技术栈，允许用 Lombok 减少样板；不引入若依大基类、权限依赖或通用框架工程。
- **事务正确性**：入队、领取、结果落库各自短事务；网络调用、等待间隔不持数据库事务；有限数据库保存重试不等于 HTTP 重试。
- **访问边界**：默认本机／私有访问，无应用登录；写接口保持 JSON 和同源检查。默认阻止本机／内网／链路本地等目标，仅按明确白名单放行测试或内部目标，云元数据地址仍阻止。
- **日志纪律**：禁止记录原始请求、响应正文、SQL 参数和敏感对象的自动 toString；异常返回固定安全摘要。
- **验证**：真实临时 SQLite、本地 HTTP fixture、注入 Clock；不得使用真实平台凭证。目标测试通过前不得宣称重构完成。

## 5. 验收矩阵

| 编号 | 验收场景 | 必须结果 |
|---|---|---|
| AC-01 | 阅读普通业务代码 | 可沿 Controller → IService → ServiceImpl → Mapper 定位，无 Service 内嵌 SQL |
| AC-02 | 新空目录启动并重启 | 仅新 V1 初始化一次；数据保留；不产生密钥 |
| AC-03 | 指向不兼容旧库 | 明确拒绝且不修改、清空或尝试迁移 |
| AC-04 | 创建平台／账号／请求／模板 | 雪花字符串 ID，无前端长整数精度损失；关系与版本冲突正确 |
| AC-05 | 原始 URL、重复头、Body 与两账号 Cookie | 本地 fixture 接收符合已声明语义的字节，账号互不串用 |
| AC-06 | 套用模板、再编辑或删除模板 | cURL 不被覆盖；已保存请求和排队快照不变 |
| AC-07 | 入队后更新 cURL／规则／计划 | 排队项仍使用创建时冻结的修订、规则和计划 |
| AC-08 | 并发领取、手动重试、重复扫描 | 条件更新和唯一约束生效，不重复发送同一活动项／发生点 |
| AC-09 | HTTP 超时、中断、崩溃恢复 | unknown、不自动重试；running 不重放 |
| AC-10 | 日界线、补执行、编辑计划、日志清理 | UTC 去重与业务日期正确，日标记独立保留 |
| AC-11 | 成功／失败／空／部分／超大／二进制响应 | 每次独立保存、详情可看、大小有界、列表无正文、HTML 不执行 |
| AC-12 | 查看敏感详情后关闭或切换 | no-store、页面清理、迟到请求不复写、不写浏览器持久存储 |
